# 为什么 nmap-cli 不做暴力破解

🌐 [Italiano](../11-brute-force.md) · [English](../en/11-brute-force.md) · **中文**

> ⚠️ 本页为机器翻译草稿，正式发布前需母语者校对（尤其是关于授权与法律的措辞）。

`nmap-cli` 不会尝试猜测凭据，也没有任何配置能做这件事。这不是缺失，而是刻意的选择，和这个工具在其他方面坚持的是同一条底线。本页解释为什么这样做，以及当你确实需要做凭据审计时，如何手工进行，并由执行者自己承担责任。

## “发现”和“强行进入”的区别

`nmap-cli` 所做的一切都是*观察*：哪些主机存活、哪些端口开放、哪些服务和版本会响应。在作用域正确、配置谨慎的前提下，这些操作几乎不留痕迹，也不会改变目标的状态。

暴力破解是另一回事。NSE 中 `brute` 类别的脚本（`ssh-brute`、`http-brute`、`smb-brute` 等）会发送*真实的*登录尝试，数量很多，一个接一个。它们不是在读取系统，而是在进入系统，或试图进入。后果的性质完全不同：

- **账户锁定。** 多次失败后，许多系统会锁定账户。锁定不会自己解除，如果你瞄准了错误的用户——一个真实的生产账户——你就给一个与测试无关的人造成了故障。
- **噪声。** 数百次失败登录会塞满日志，触发 IDS 和 SOC 的告警。被动枚举不会被注意到；暴力破解按定义就会。
- **脆弱性。** 配置不当或负载较高的服务，可能在大量请求的冲击下降级甚至宕机。
- **法律风险。** 在许多司法管辖区，对未明确授权以这种方式测试的系统尝试认证，本身就是独立于单纯扫描的违法行为。

## 为什么我们不自动化它

整个工具的原则是：有真实后果的操作，绝不能因惯性而启动。作用域要签名，默认是 dry-run，每次运行都写入审计日志。而一个引擎如果在拿到扫描结果后，自行把开放服务映射到对应的 `brute` 脚本并串联执行，做的恰恰相反：它把一个重大决定——“我即将尝试攻破这些系统的认证”——变成了一条命令的副作用。错误正是这样变成事故的。

还有技术上的原因。`nmap-cli` 的其余部分从不手工拼接命令行，也从不把字符串传给 shell：标志过滤和参数列表就是为此而设。而暴力破解引擎必须传入 `--script-args`（userdb、passdb、阈值、超时），这正是代码其余部分小心排除的那类字符串。把它重新放回工具里，就等于把工具本要避免的风险又带了回来。

最后，还有诚实的原因。README 用三种语言写明：`nmap-cli` 不执行暴力破解。这是一个让工具在任何审视者面前都站得住脚的承诺。只要它为真，就有价值。

## 确实需要时，该怎么做

凭据暴力破解在审计中是有用的：检验某个服务是否接受弱口令、锁定策略是否生效、某个默认账户是否被遗留启用。这是一项正当的活动——前提是在你自己的系统上、在靶场里，或者在**明确**涵盖凭据测试（而不仅是扫描）的书面授权下进行。

这种情况下，直接运行 Nmap。它只有一行之遥，而且应当保持为一个明确的选择：

```sh
nmap -p 22 --script ssh-brute \
  --script-args "userdb=users.txt,passdb=pass.txt,brute.firstonly=true,brute.threads=2,brute.delay=5,unpwdb.timelimit=10m" \
  192.0.2.10
```

几条能减少伤害的注意事项：

- **`brute.firstonly=true`** 一找到第一个有效凭据就停止，而不是继续攻击该账户。
- 较低的 **`brute.delay`** 和 **`brute.threads`** 把尝试拉开：更少的噪声，更低的锁定风险。
- **`unpwdb.timelimit`** 给总时间设上限，让操作在已知的时间窗内结束。
- **使用你自己的列表**（`userdb`/`passdb`）：清楚知道自己在尝试什么，本身就是审计的一部分。不指定时，Nmap 会使用它的默认列表。
- **先过作用域。** 在运行任何东西之前，用 `nmap-cli verifica` 校验目标，或手工检查作用域文件。这样直接运行的 Nmap 不会替你做这件事。

[scripts/nmap_workflow.sh](../../scripts/nmap_workflow.sh) 中的速查表收集了最常见的 `brute` 脚本（SSH、FTP、HTTP、HTTP 表单、SMB、MySQL、Oracle、MongoDB），每个都附有风险说明，以及 `brute` 库选项的完整清单。它是参考材料：命令由你手工运行，运行前先读懂它们做什么。

## 一句话总结

| | |
|---|---|
| `nmap-cli` 会自动暴力破解吗？ | 不会，刻意如此。没有对应配置，CLI 也不构造那些命令。 |
| 我还是可以做吗？ | 可以，直接用 `nmap`，由你自己负责，并需书面授权。 |
| 命令在哪里？ | 在速查表 [scripts/nmap_workflow.sh](../../scripts/nmap_workflow.sh) 中，作为参考。 |
| 为什么这样选择？ | 凭据攻击是一个决定，不是流水线里的一个自动步骤。 |
